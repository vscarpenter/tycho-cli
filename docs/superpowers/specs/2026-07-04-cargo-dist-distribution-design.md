# Phase 5B design — distribution via cargo-dist (+ Homebrew, folding in 5C)

Status: approved 2026-07-04. Second sub-project of Phase 5 (spec §10 "Ship":
`cargo-dist` release automation, `cargo install` instructions, Homebrew tap).
The single approval gate was the design below.

## Goal

Set up automated cross-platform release binaries and installers so a pushed
version tag produces a GitHub Release with prebuilt archives plus shell,
PowerShell, and Homebrew installers — without cutting an actual release until
explicitly approved.

## Nature of this sub-project

This is release **ops/config**, not library code: the deliverable is
generated CI + config + docs, so there is no unit-testable surface. The
validation gate is `dist plan` (a dry run that resolves the full release
graph) succeeding, plus `cargo build --release` still passing. TDD does not
apply; frequent commits and a green `dist plan` do.

## Decisions (from the design gate)

- **Tool:** [cargo-dist](https://opensource.axo.dev/cargo-dist/) (`dist`),
  installed locally, `dist init` run non-interactively to generate config and
  `.github/workflows/release.yml`.
- **Targets (full matrix):** `aarch64-apple-darwin`, `x86_64-apple-darwin`,
  `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`,
  `x86_64-pc-windows-msvc`.
- **Installers:** `shell`, `powershell`, `homebrew` (Homebrew folds in 5C).
- **Homebrew tap:** a new public repo `vscarpenter/homebrew-tap`; cargo-dist
  pushes the generated formula there on release, so
  `brew install vscarpenter/tap/tycho` works after the first real release.

## Hard boundary — no release without approval

5B wires the automation and dry-runs it only. Cutting a real release (a
version bump + `git tag vX.Y.Z` + push, which publishes binaries publicly and
pushes the Homebrew formula) is a **separate, explicitly-approved** step. `dist
plan` proves the config is valid without publishing anything.

## What gets created / changed

1. **cargo-dist config.** `dist init` writes `[workspace.metadata.dist]` (or a
   `dist-workspace.toml`, per the installed dist version) with the targets,
   installers, `ci = "github"`, the tap repo, and the dist version. Reviewed by
   hand after generation; hand-editing limited to the chosen targets/installers
   /tap if init defaults differ.
2. **`.github/workflows/release.yml`.** Generated by `dist init`/`dist
   generate`. Triggers on tags matching the dist tag pattern (`v*`). Committed
   as generated; not hand-authored.
3. **`Cargo.toml`.** May gain a `[profile.dist]` and the `[workspace.metadata.
   dist]` block. The `version` stays `0.1.0` (no bump in 5B).
4. **`vscarpenter/homebrew-tap` repo.** Created public and empty (cargo-dist
   populates it on release). Created via `gh repo create`.
5. **README Install section.** Add: a one-line shell installer and PowerShell
   installer (the URLs cargo-dist will serve from the release), a Homebrew
   line, a prebuilt-binary note, and `cargo install --git
   https://github.com/vscarpenter/tycho-cli`, keeping the from-source path.
6. **`docs/learning/phase-5.md`.** A short "5B · Distribution" section: what
   cargo-dist generates, the tag-triggered release model, and the
   host/target/installer split (a Go/Rust cross-compilation contrast).
7. **`tasks/todo.md`.** Record the 5B gate; mark 5C (Homebrew) folded in
   pending a real release.

## Validation

- `dist plan` (or `dist build --artifacts=lies`/`--no-local-builds` as the
  installed version supports) resolves the release graph across all five
  targets and both installers with no error.
- `cargo build --release` still succeeds and the existing CI (`ci.yml`) stays
  green.
- `git` tree review of the generated `release.yml` for anything surprising
  (no secrets, no unexpected publish steps beyond GitHub Releases + the tap).

## Risks / notes

- cargo-dist versions differ in config location (`Cargo.toml` metadata vs
  `dist-workspace.toml`) and command surface (`dist plan` vs older `cargo dist
  plan`). The plan pins the installed version into the config so CI matches
  local.
- The generated `release.yml` needs the default `GITHUB_TOKEN`; pushing to the
  separate tap repo needs a token with access to it. cargo-dist documents this
  as a `HOMEBREW_TAP_TOKEN`/PAT secret — 5B documents the requirement; wiring
  the secret is part of the first real release, not the dry run.

## Scope guard (YAGNI)

No npm/msi installers, no auto-update, no extra artifact signing/notarization,
no version bump, no real release in 5B.
